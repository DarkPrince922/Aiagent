# Jarvis for Android

Нативный Android-ассистент для OpenAI-совместимого API. По умолчанию используется
`https://aiprovider.duckdns.org/v1` и модель `claude-opus-4-8`; оба значения меняются
в настройках приложения.

## Что уже работает

- чат через `POST /chat/completions`;
- локальные настройки endpoint, модели, API-ключа и system prompt;
- точная диагностика HTTP/API/TLS/сетевых ошибок и проверка подключения в настройках;
- очередь запросов в SQLite и повтор через WorkManager после восстановления сети;
- многошаговый agent loop с возвратом результатов инструментов модели;
- режим агента без лимита шагов с ручной остановкой и защитой от повторяющихся циклов;
- отдельные автономные задачи: работа до проверенного результата, pause/stop и журнал ключевых событий;
- автономная задача продолжается при закрытом приложении: WorkManager держит её в foreground-сервисе,
  уведомление показывает текущий шаг и даёт кнопки «Стоп» и «Пауза» прямо из шторки;
- уведомление о результате: завершение, остановка и ошибка приходят, даже если приложение закрыто;
- вмешательство по ходу: указание, отправленное запущенной задаче, попадает в диалог перед следующим
  шагом — контекст и checkpoint сохраняются, работа не прерывается; для остановленной или завершённой
  задачи указание возвращает её в работу;
- checkpoint после каждого шага и автоматическое возобновление WorkManager после обрыва сети или перезапуска приложения;
- несколько сохраняемых чатов с переключением и удалением истории;
- Google News/Bing RSS/DuckDuckGo Lite search с fallback и устойчивое чтение публичных HTTPS-страниц:
  повтор при таймаутах и 5xx, поддержка не-HTML ответов, понятная причина отказа вместо общей ошибки;
- SSH-профили, password/private-key auth, pinning fingerprint и удалённые команды;
- удалённый SSH operation ledger: после reconnect агент опрашивает ту же операцию и не повторяет команду вслепую;
- заметки, HTTP/DNS/JSON/SHA-256/Base64/UUID, калькулятор и статус устройства;
- браузер, карты, набор номера, письма, календарь, таймеры, share и clipboard;
- голосовой ввод, каталог инструментов, тёмная terminal-тема и анимированные переходы;
- выбор инструмента подставляет редактируемое задание в черновик и не отправляет его сам;
- в обычном чате SSH и внешние действия требуют подтверждения; автономная задача не спрашивает
  подтверждений и работает по гранту: один выбранный SSH-профиль плюс read-only HTTPS-запросы (GET).
  Всё, что вне гранта, инструмент отклоняет сам, не останавливая задачу;
- API-ключ и SSH-секреты шифруются AES-GCM ключом из Android Keystore.

## Свой сервер

В поле endpoint можно указать адрес собственного сервера с OpenAI-совместимым API
(Ollama, llama.cpp server, vLLM). Для адреса в локальной сети разрешён обычный `http://`:

```
http://192.168.1.50:11434/v1
```

Наружу по-прежнему только `https://` — незашифрованный API-ключ в интернете недопустим.
Проверка выполняется по фактически разрешённому IP, а не по виду строки.

## Обмен файлами с агентом

Агент умеет принимать и отдавать текстовые и JSON-файлы.

- **Передать файл агенту**: «Поделиться» → Jarvis. Файл попадает в рабочую папку приложения,
  разрешения не нужны. Поддерживаются `.txt`, `.json`, `.md`, `.csv`, `.log`, `.yaml`, `.xml`
  до 512 КБ.
- **Получить файл от агента**: инструмент `send_file` открывает системное меню отправки.
- Инструменты: `list_files`, `read_file`, `write_file`, `send_file`.

Имя файла приходит от модели и считается недоверенным: каталоги отбрасываются целиком,
расширение приводится к текстовому, выйти за пределы рабочей папки невозможно.

## Порядок работы агента

По умолчанию включён режим «сначала ответ, потом действия»: модель обязана сперва написать
текстом, что поняла и что собирается делать, и только затем вызывать инструменты. Этот текст
появляется в чате отдельным сообщением **до** выполнения команд, так что видно намерение, а
не только результат. Отключается в настройках.

## Локальная модель (офлайн)

В настройках переключатель «Облако / Локально». Локальный движок — llama.cpp, собирается из
исходников на этапе сборки (CMake FetchContent, тег `b10259`), только под `arm64-v8a`.

Модель скачивается прямо из приложения: Настройки → Движок → Локально → «Скачать» напротив
нужного варианта. Ни компьютер, ни файловый менеджер не нужны.

Файл кладётся в собственный каталог приложения (`Android/data/app.jarvis/files/models`) —
именно поэтому не требуется ни одного разрешения на доступ к памяти: `/sdcard/Download`
приложению на Android 11+ уже недоступен.

Загрузка идёт в foreground-сервисе, поэтому переживает сворачивание приложения, показывает
прогресс в уведомлении и возобновляется с прерванного места после обрыва связи (HTTP Range),
а не начинает гигабайты заново. Перед стартом проверяется свободное место.

Рекомендуется Qwen3 4B Q4_K_M (~2.5 ГБ) — в своём классе заметно лучше остальных в tool calling.
Рядом есть поле для своей ссылки на любой `.gguf`. Там же настраиваются контекст и число потоков
(0 — подобрать по числу ядер; больше потоков, чем больших ядер, только замедляет).

Вызовы инструментов ограничены GBNF-грамматикой, которая строится из тех же JSON-схем, что
уходят в облако: модель физически не может выдать несуществующее имя инструмента или сломанный
JSON. Грамматика ленивая — свободный текст не ограничен, правила включаются только после того,
как модель сама начала `<tool_call>`.

Ограничения, о которых стоит знать: контекст на устройстве на порядок меньше облачного (история
подрезается автоматически), длинный вывод инструментов обрабатывается минутами, а телефон при
непрерывной нагрузке уходит в троттлинг. Для долгих автономных задач с SSH локальный движок
не предназначен — это режим для офлайн-чата и простых локальных инструментов.

## Запуск

Откройте корневую папку в Android Studio, дождитесь Gradle Sync и запустите модуль
`app` на Android 8.0 или новее. В настройках приложения укажите API-ключ провайдера.
Из терминала: `./gradlew :app:assembleDebug` — версия Gradle зафиксирована в wrapper.

Разрешите уведомления при первом запуске: на Android 13+ без них не будет видно ни прогресс
автономной задачи, ни кнопок управления в шторке.

## Сборка на GitHub

Workflow `.github/workflows/android.yml` собирает debug APK после каждого push в
`main`, для pull request и при ручном запуске. Готовый файл находится на странице
запуска GitHub Actions в артефакте `jarvis-debug-apk`.

Debug APK подписывается публичным development-ключом `app/jarvis-debug.keystore`,
чтобы последующие тестовые сборки устанавливались как обновления. Этот ключ нельзя
использовать для production-релиза или публикации в Google Play.

Проект намеренно не хранит API-ключи и SSH-секреты в репозитории. Все сетевые инструменты
(`web_fetch`, `web_search`, `http_request`, `open_url`) проходят через единую политику `UrlPolicy`:
разрешён только HTTPS, запрещены credentials в URL и любые адреса, резолвящиеся в loopback,
RFC1918, link-local, CGNAT или IPv6 ULA — включая каждый шаг цепочки редиректов. Модель видит только
ID и публичные параметры SSH-профиля; пароль и private key в контекст не передаются и не
расшифровываются при обычном показе списков.

Для возобновляемых SSH-операций на тестовом сервере нужны POSIX `sh`, `base64`, `nohup`, `dd`, `wc`,
`tr` и `find`. Команда выполняется из `$HOME` — так же, как в обычном чате; журнал операций лежит
в `~/.cache/jarvis-agent/ops` и автоматически чистится от записей старше 7 дней.
Команды запускаются без PTY, поэтому `sudo` должен быть non-interactive и ограничен нужными для теста командами.
